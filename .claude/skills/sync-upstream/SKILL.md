# Sync the fork with upstream

The fork's changes live as a patch queue in `scripts/daily-patches/`:

- `manifest.json`: the upstream base tag, the fork version, and for each patch its `reason`, `notes`, `obsoleteWhen` and manual `verify` steps. `repoOnly` lists fork tooling that is never patched; `regenerate` lists files rebuilt instead of patched (`package-lock.json`).
- `patches/NNNN-<id>.patch`: generated by `git format-patch` from the branch `daily/<baseTag>`, which has one commit per patch (subject `<id>: <title>`) on top of the upstream tag.
- `patches.sh`: `check`, `generate`, `verify`, `audit`, `build` (run it without arguments for usage).

Conflicts are resolved **once**, while replaying the patches on the new tag in `daily/<NEW>`. Upstream `<NEW>` is then merged into `main-synced-to-<NEW>`, and the merge takes its tree from `daily/<NEW>`. History keeps the upstream merge, and `main` always equals the patched upstream tag.

## Rules

- Never add `Co-Authored-By: Claude` or any other Claude attribution to commits, patches or PR descriptions.
- Replay patches in a scratchpad worktree. The local `daily/<NEW>` commits from `git am` are part of the workflow and can be rewritten freely.
- Never push, open PRs or publish: the user does that. Ask before creating the merge commit.
- Stop and ask if the right resolution of a conflict isn't clear from the manifest `reason`/`notes` and the upstream diff.

## Steps

### 1. Preflight

```bash
git status --short          # must be clean
git remote get-url upstream || git remote add upstream git@github.com:react-native-webrtc/react-native-webrtc.git
git fetch origin && git fetch upstream --tags
BASE=$(node -p "require('./scripts/daily-patches/manifest.json').upstream.baseTag")
```

Keep `BASE`; step 6 overwrites it in the manifest, and step 7 still needs it.

### 2. Pick the target release

Use the version the user gave. Otherwise, list the latest releases with `gh release list -R react-native-webrtc/react-native-webrtc --limit 5` and confirm the choice. Stop if `NEW` equals `BASE`.

### 3. Preview

```bash
scripts/daily-patches/patches.sh check $NEW    # per patch: clean | 3way | conflict | already-upstream (exits 1 on conflict)
git log --oneline --no-merges $BASE..$NEW
```

- `fork-packaging` always conflicts on the `"version"` line in package.json, because upstream bumps it. That's expected.
- If a patch that isn't clean has an `obsoleteWhen`, or upstream touched the files of an `upstreamable` patch, read `git diff $BASE $NEW -- <files>` and decide whether to drop or trim the patch.
- Daily depends on these fork APIs, so upstream changes around them need the most care:
  - react-native-daily-js calls `WebRTCModule.setDailyAudioMode/setAudioDevice/getAudioDevice/enableNoOpRecordingEnsuringBackgroundContinuity`.
  - daily-js calls `MediaStreamTrack._switchCamera()/_getCameraFacingMode()` and `navigator.mediaDevices` `devicechange`, and lists audio outputs (`kind: 'audio'`) from `enumerateDevices`.
  - Upstream's `enumerateDevices` is bypassed: if upstream changed it, port the change into the Daily devices manager.

Summarise for the user: the table, the patches to drop or trim, and the expected conflicts. Agree on the plan before continuing.

### 4. Replay the patches on the new tag

```bash
WT=<scratchpad>/daily-$NEW
git worktree add -b daily/$NEW $WT $NEW
git -C $WT am -3 --whitespace=nowarn "$PWD"/scripts/daily-patches/patches/*.patch
```

When a patch stops:
- Resolve it so it keeps upstream's new behaviour **and** the patch's intent. Then `git add` and `git am --continue`.
- `git am --skip` a patch you agreed to drop. If a patch is partly upstream, keep only the rest.
- In `fork-packaging`, set `"version": "$NEW-daily.1"`.
- Keep the `<id>: <title>` subjects. Update the message body if the patch's meaning changed.

### 5. Merge upstream into the sync branch

```bash
git switch -c main-pre-syncing-to-$NEW origin/main
git switch -c main-synced-to-$NEW
git merge --no-ff --no-commit $NEW                                   # conflicts expected; don't resolve by hand
EX=(':!package-lock.json' ':!.claude/' ':!scripts/daily-patches/')   # manifest regenerate + repoOnly
git checkout daily/$NEW -- . "${EX[@]}"
git diff --cached --name-only --diff-filter=A daily/$NEW -- . "${EX[@]}" | while read -r f; do git rm -q "$f"; done
git checkout --ours package-lock.json && npm install && git add package-lock.json
git diff --name-only --diff-filter=U                                 # must print nothing
test "$(git rev-parse 'MERGE_HEAD^{commit}')" = "$(git rev-parse "$NEW^{commit}")" && echo "merging $NEW"
```

The `git rm` line removes files that upstream deleted, or that a dropped patch had added.

### 6. Regenerate patches and update the manifest

1. In `manifest.json`, set `upstream.baseTag` to `NEW`, `patchBranch` to `daily/NEW` and `forkVersion` to `NEW-daily.1`. Remove dropped patches; add an entry for any new patch, with the same fields as the existing ones.
2. Run `scripts/daily-patches/patches.sh generate daily/$NEW`. It rewrites `patches/`, syncs each entry's `file`/`files` and the patch order, and fails if commits and entries don't match.
3. Set each patch's `lastVerified` to `{ "tag": "NEW", "result": "clean" | "3way" | "conflict-resolved" | "trimmed" }`, and update `notes`/`obsoleteWhen` with anything you learned.
4. `git add scripts/daily-patches`

### 7. Verify

All three must pass:

```bash
TREE=$(git write-tree)
scripts/daily-patches/patches.sh verify $NEW $TREE        # staged merge == patches applied to NEW
scripts/daily-patches/patches.sh audit $BASE $NEW $TREE   # nothing from BASE..NEW was lost
scripts/daily-patches/patches.sh build                    # lint, bob build, index.d.ts imports/exports
```

- **`audit`** fails if a file differs from `NEW` without belonging to a patch: either a lost upstream change, or a Daily change outside the patch queue. It also marks `REVIEW` on patched files where upstream's change isn't present verbatim. For each `REVIEW`, compare `git diff $BASE $NEW -- <file>` with the merged file, confirm the change was adapted on purpose, and tell the user.
- **`build`** fails if `index.d.ts` misses a new upstream export. Fix that in the `daily-type-definitions` patch (in `daily/$NEW`), then redo step 6.

### 8. Self-test on device

Nothing above compiles the Java/Objective-C patches or exercises them at runtime. Use the `daily-selftest` skill: it installs this checkout into `examples/DailySelfTest` with `npm pack` (so the uncommitted merge is included), builds release builds with `expo prebuild`, and runs the automated checks on an Android emulator and/or iOS simulator.

- Every check must pass or be an expected skip. If upstream added a Daily-facing change, add a check there.
- If the app doesn't build with the new upstream (e.g. it needs a newer React Native), bump the versions in `examples/DailySelfTest/package.json` through the `daily-selftest-app` patch.
- The checks it can't automate (audible routing, Bluetooth, real headset plug, iOS background) stay with the user, on a real device with a Daily app.

### 9. Hand off

- After the user approves, commit the merge as `Merge upstream react-native-webrtc $NEW`.
- `git worktree remove $WT`.
- Tell the user which branches are ready to push (`main-pre-syncing-to-$NEW`, `main-synced-to-$NEW`, `daily/$NEW`), and give them a PR description to paste: the `check` table, the `audit` output with how each `REVIEW` was resolved, the build and self-test results, and the patches dropped or changed.
- Remind the user that react-native-daily-js must widen its `@daily-co/react-native-webrtc` dependency and peerDependency before apps can install the new version. A caret range on a prerelease (`^124.0.6-daily.1`) doesn't match `124.0.7-daily.1` or `125.x`. Show the current range with `grep react-native-webrtc <react-native-daily-js>/package.json`.

## Changing the fork between syncs

Every change on `main` outside `repoOnly` must also be in the patch queue, or the next sync loses it. `audit` will flag it.

1. In a worktree of `daily/$BASE`, add a commit `<id>: <title>` (plus a manifest entry), or fold the change into an existing patch: `git commit --fixup=<sha>`, then `git -c sequence.editor=: rebase -i --autosquash $BASE`.
2. Run `scripts/daily-patches/patches.sh generate`, then `patches.sh verify $BASE $(git write-tree)`.
3. A fork-only release bumps `"version"` to `$BASE-daily.N+1` in the `fork-packaging` commit, on `main`, and in `manifest.forkVersion`.
